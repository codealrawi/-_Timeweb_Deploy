Четыре архитектурные парадигмы
🏛 Монолит
Single-container Docker
Минимальная сложность, кратчайший MVP. Вертикальное масштабирование. Ограничен пулом потоков (200–400). Деградация при R → R_sat по M/M/1.
α ≈ 1.7 · быстрая деградация
🏗 Three-tier
Docker Compose · 3 сервиса
Frontend / backend / БД. Промежуточное решение — разделение бизнес-логики и данных без полной декомпозиции. Подходит до ~1500 VU.
Частичная масштабируемость
⚙ Микросервисы
Kubernetes 1.28 · 5 подов
API-gateway, auth, content, moderation, analytics. Горизонтальное автомасштабирование (HPA). Линейная деградация — ΔR_sat ≈ 900 RPS на под.
α ≈ 0.9 · стабильность
⚡ Serverless
OpenFaaS · pay-per-use
Автоматическое масштабирование функций. Эффект «холодного старта» (180 мс при 10 VU). Оптимален при нерегулярной нагрузке.
×0.8 · стоимость инфраструктуры *

⚡ Реальный нагрузочный тест · concurrent VU прямо сейчас
Каждая архитектура реализована на сервере с аутентичными отличиями: монолит — общий lock БД, three-tier — каскад из 3 пулов (200/100/50), микросервисы — fan-out через Kubernetes-style HPA-пулы, serverless — без лимита параллелизма + cold start. Сервер запускает asyncio.gather(N) внутри и возвращает измеренные RT/RPS.
Нажмите кнопку — запустится реальный тест на сервере. Каждая архитектура отвечает на N concurrent запросов через asyncio.gather.

Алгоритм выбора архитектуры · пороговые значения нагрузки
Шаги алгоритма:
1. Определить ожидаемую пиковую нагрузку Npeak (VU) → выбор базовой парадигмы.
2. Оценить профиль нагрузки. Если пиковый RPS / средний RPS > 5 (нерегулярная нагрузка) → добавить serverless-компоненты для аналитики.
3. Учесть специфические требования: интеграция с госреестрами → API-Gateway; GDPR/ФЗ-152 (PHI) → отдельный изолированный сервис.
★ Рекомендуемая комбинация для медицинских платформ среднего масштаба
Three-tier база + микросервис модерации контента + serverless для аналитики — «три в одном». Минимальные первоначальные издержки при сохранении пути к полной микросервисной декомпозиции по мере роста системы.
Ключевые выводы исследования
✓
Микросервисная архитектура обеспечивает наилучшую масштабируемость: RTavg = 89 мс и ε = 0.3% при 5000 VU против полного отказа монолита при той же нагрузке.
✓
Тест Манна–Уитни (U = 0, p < 0.001) подтвердил статистическую значимость превосходства микросервисов при нагрузках ≥ 500 VU.
✓
Serverless экономически выгоден (×0.8 от стоимости микросервисной) только при нерегулярном трафике; при постоянной высокой нагрузке — сопоставим или дороже.
✓
Получены пороговые значения: монолит — до 300 VU, three-tier — 300–1500 VU, микросервисы — ≥ 1500 VU.
✓
Обоснован комбинированный подход — three-tier + микросервис модерации + serverless для аналитики — оптимален для большинства медицинских социальных платформ.
